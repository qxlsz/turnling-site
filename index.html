The problem

Editors reach coding agents through Agent Client Protocol (ACP) adapters, and some adapters tell the editor which files each request changed. A subagent can outlive the request that started it. When its late edit arrives, the adapter credits it to whichever request is current. The report then has the right request id and the wrong files, and the editor cannot tell.

What we found

We state the property such reports should keep, an origin-attribution invariant, and check it with Turnstile, which runs an unmodified adapter under the event orders a provider model allows.

581 of 956

39 of 111

0
Codex schedules that misattribute with dispatch-time binding, in every scenario of Table I

Single live runs with the real Codex and Claude Code CLIs show that these orders occur. They say nothing about how often.

The fix

Bind each subagent to the request that dispatched it, read from the spawn item, not to the request that is current when its events arrive. On Codex this removes every misattribution in our scenarios. The cost: when the link is uncertain, the adapter leaves the edit out and flags the report. Binding at the subagent’s start instead still fails in 174 of the 956 schedules.

The limit

On the typed Codex 0.160.1 wire, no adapter meeting stated conditions attributes exactly in all legal executions: two executions can give the adapter identical input, yet an edit belongs to A in one and to B in the other. Origin links on the event stream suffice. Codex 0.162.0 adds a rootTurnId field that, by our source reading, provides them.
